# 实现说明

[文档导航](README.md)

本文说明当前实现与边界。接口字段和调用方式以 [接口文档](external-api.md) 为准，签名与计费的详细规范分别见 [SM3 协议](sm3-auth.md) 和 [里程计费](mileage-fares.md)。

## 存档读取与地图目录

`WorldReader` 读取单个维度目录或 ZIP 中的 MTR 3.x MessagePack 数据：车站、站台、线路、车厂、股道和生成路径。ZIP 原样读取，不解压或修改原存档。MTR 文件可能遗留旧尾字节，解码器与 Java 行为一致，只消费首个完整 map。

原始 64 位 MTR ID 以字符串输出，避免 JavaScript 精度损失。车站标识包含维度；车厂筛选同时使用维度与车厂 ID。

地图目录与可售运行图分别保存。`mtr_depots` 保留车厂配置和规划诊断，`mtr_depot_sidings` 保留股道；没有生成班次不代表该车厂不存在。已删除地图对象的历史记录仍可供旧行程引用。

## 方向班次与标识

`RoutePlan` 按车厂配置的路线顺序拼接站台序列，只移除相邻重复站台，再校验保存路径中的 `stop_index`、站台 ID 和顺序。路径与配置不一致时要求在 MTR 中重新生成路径，不凭空补站。

每条配置路线对应一个乘客方向班次，而非把整个车厂往返周期当作一趟。明确配置的单线路环线保留原顺序；同一停站索引上的反向站台遍历合并为一次停站。

- 数据库 `id` 是出票及详情查询的主键。
- `trip_code` 为“车厂 ID + 股道 ID + 趟次”，供显示使用。
- `run_number` 从 1 开始，按运营日、车厂及股道内的发车顺序编号，分页不重新编号。
- `train_number` 是可选显示车次号，无唯一约束。按线路名的 `|` 分段提取 D/G/C/S 加 1–16 位数字的匹配段，保留前导零。

同一车次号可在同日重复出现。选择行程需结合日期、区间、时刻与班次 ID；重复经过同一车站时使用明确站序。

## 股道车辆上限

MTR 存档 `max_trains` 是零基上限。`max_trains=0`、`unlimited_trains=false` 表示最多一列车，不是关闭自动发车。有限模式下展示 `vehicle_limit=max_trains+1`，无限模式为 null。

计划发车表与物理车辆就绪状态不同。多股道离线分配规则见 [导入指南](importing.md)。

## 运动模型与里程

`Timetable` 参考 MTR 3.x 的 `Rail.getLength()`、`TrainType.getSpacing()`、`Train.getRailSpeed()`、`Train.simulateTrain()` 与 `TrainServer.startUp()`，以每秒 20 tick 模拟自由运行：

- 使用路径轨道几何长度，限速从 km/h 换算为每 tick 方块数。
- 读取股道加速度 `acceleration_constant`，保留三位小数；非正值回退到 0.01 m/tick²。
- 根据剩余距离制动，按 MTR 规则继承站台前段限速并处理停车、起步和停站时间。
- 使用车型间距和车辆数处理出库位置与折返跳转，兼容旧车型名称映射。

这与旧的 `Siding.generateTimeSegments` 图定估算存在差异。当前模拟不包含信号、服务器延迟和实时车辆状态，也没有保证与游戏内实际到发时刻完全一致。

每个方向班次首站从零累计实际行驶里程，1 方块按 1 米。折返因车长发生的位置跳转不计入里程。一 tick 跨过多段轨道时按实际穿越长度拆分，保存各标称限速档累计值，乘车区间用两端差值计价。标称限速分类与瞬时运行速度不同，具体口径见 [计费说明](mileage-fares.md)。

## 客票、库存与幂等

当前一张客票对应一名旅客、一个乘车联。13 位票号由出票方三位前缀和随机部分构成，PNR 为六位订座记录号。

库存按相邻停站区间占用，支持不重叠区间复用。出票和退票使用事务及列车行锁，避免并发超售；退票释放库存，重复退票不重复记账。当前拒绝已发车客票退票。

幂等请求以出票方和 `Idempotency-Key` 识别。相同请求重试返回原票，改内容复用同一键返回冲突；网络重试需重新生成签名时间戳和 nonce。新票保存出票时的单价版本与计费快照，后续改价不影响原票。

## 机构、归属与权限

- 管理员、出票方和运营方使用不同身份。前端菜单仅决定展示，后端逐请求校验权限。
- 车厂归属作用于其各路线班次及后续导入；已有客票的班次不能更换运营方。
- 运营方可开启销售白名单；开启后空列表拒绝新销售，关闭后允许启用出票方销售。
- 撤销销售授权不影响原票查询、退票及原请求的幂等重试。停用机构会阻止其独立密钥认证。

## 证件与附加信息

旅客证件跨机构共用，通过类型、归属地与号码保证唯一性。修改带版本校验并保存前后值、原因和操作方；出票时保存证件快照，后续更正不改历史客票。

运营方只能管理自身承运客票的 TLV 附加信息。记录采用追加与撤销模式，保留原值和审计，重复标签不覆盖历史项。二进制格式、长度约束和接口见 [运营方与 TLV 接口](external-api.md)。

本项目是内部客票与库存协议，未接入付款、航空清算或 IATA 认证体系。
